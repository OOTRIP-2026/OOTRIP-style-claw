# 实时试衣UI接入：待用户验证

日期：2026-10-26。用户接受照片/实时模式切换、衣橱选衣及隐藏开发信息的建议，并授权接入现有UI。助手未代跑检查/构建/真机或模型调用。

## 已有真实基线

原生桥接首次真实测试截图显示发送39帧、显示11帧、160×90，终态first-frame-limit表示后端收到首帧后10秒按时结束。用户明确反馈效果很好；额度说“可能24，忘记开始前多少”，只能记录估计，不能标精确账单。该次调用机会仍已用，本轮不清除预约或自动发起新调用。

## UI行为

- 正式试衣间新增“照片试衣 / 实时试衣”，实时入口进入原生camera页面；返回照片模式复用上一页，保留原照片模式选择/草稿，不将实时预览自动写入搭配或相册。
- 实时页使用浅色试衣镜、原摄像头小窗、生成画面区、横向衣橱、单件选择与明确开始/结束。Canvas从页面就绪即存在，等待结果时只显示占位，不以原画面冒充AI结果。
- 衣橱只读现有原仓储中有图片的上衣/内搭，排除示例和已移除记录，未购买保留角标。当前提示词仍为上衣，因此未把其他分类擅自开放为已支持。相册选图仍可用，不自动入库。
- 所选衣物从正式照片试衣页带ID预选，读取时核对仍存在；换图重新同意，过期读回不覆盖新选择，读取失败显示提示。当前单件图片2MiB限制不变。
- “连接设置”单独承载地址/开发令牌、保存检查及折叠诊断。主画面用中文状态，不展示帧数或内部结束代码。连接配置仅进程内存保存，重启需重新配置；可复用“我的”已有内存开发令牌，地址不写全局配置、不改现有HTTP服务或正式业务存储。
- 当前30秒总连接/后端首帧后10秒先到结束、明确同意、单次预约及默认费用边界保持。没有新增真实机会；当前“不可用/机会已使用”是如实展示，不用假可用按钮掩盖已消耗预算。

## 用户运行

1. 根目录运行`npm.cmd run check`，通过再运行`npm.cmd run build`。
2. 微信工具切回“普通编译”，重新真机调试。从原正式入口进入试衣间，点击顶部“实时试衣”。也可用原生开发页入口查看，但不再需要专门编译模式来进入正式试衣页。
3. 检查浅色预览、两种模式、空衣橱提示、真实衣橱及未购买角标、点击选衣高亮、相册取消、返回照片模式后原单品是否保留。先不点真实开始，不消耗额度。
4. 连接设置填已验证电脑地址及开发令牌，保存检查，确认信息不混入主界面，关闭再打开值仍在；重启不承诺恢复凭据。已用一次机会状态正常保留。
5. 本机相机预览可独立开启/关闭；隐藏或退出页面停止采集。为验证UI不需要新增付费调用。完整UI+AI组合仍需之后单独授权及真机验收，不以此前实验视频替代。

## 当前限制

仍是电脑后端、开发访问凭据、低清晰度2fps媒体桥接；没有新增独立部署、正式微信网络/资质验收、全品类或多语言完成声明。本轮不接截图保存/整套保存、不改已验其他业务。样式是复用当前项目的实现候选，未获真机视觉确认，不作为最终高保真稿。


2026-10-26 修订：左侧大画面+右侧竖向分类，预览不再放在独立卡片中。重建后检查摄像头占主画面、右侧分类与下方选衣。手机连接填写电脑当前IPv4（本次用户提供10.15.145.64:3000），不用127.0.0.1。保留已用预约，不通过此轮视觉验证新增真实调用；检查手机回环地址应在发请求前提示。


## 2026-10-26 选衣修订真机验证

本批用户已授权助手执行本地检查/测试/构建；供应商调用不包含在此授权。微信工具重新编译并重新进入真机调试后：

1. 点击上衣，在右侧衣物栏点击“上传上衣”，选择2MiB内图片；图应立即出现并打勾，下方已选列表也应显示。
2. 再上传另一件上衣：两张图保留可浏览，但仅后一件打勾；点击前一件可重新切换。
3. 选择裤子，可与上衣同时选中；选择套装后上衣、裤子、内搭应取消，反向选择任意上述单件也取消套装。
4. 切换分类不清空已选；移除时取消选中并清除同意；取消相册或坏图不破坏原选择。
5. 后端仍返回旧attemptUsed，不删除记录、不开放新机会；本轮查看选择和本机摄像头即可。多件AI生成效果、真实Canvas和布局需后续用户验证，不由替身测试代替。
