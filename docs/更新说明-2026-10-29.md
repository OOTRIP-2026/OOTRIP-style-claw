## 五、手动推送到 GitHub

当前 `.env`、`node_modules/`、`.runtime/` 等已经列入 `.gitignore`。本次新增素材目录和构建文件需要一并提交。

在 Windows 的 CMD 窗口中逐条执行，任一步报错先停下：

```bat
cd /d C:\Users\86136\Documents\Codex\2026-10-25\new-chat\outputs\style-claw
node build.mjs
git status
git add -A
git diff --cached --stat
git commit -m "feat: refine fitting room and home interactions"
git pull --rebase origin main
git push origin main
```

说明：

- `git diff --cached --stat` 用于在提交前查看将要上传的文件。
- 提交后先拉取并接上远程更新，避免之前遇到的 `fetch first`。
- 推送期间图片较多可能较慢，等待上传完成、出现 `main -> main` 并返回命令提示符。
- 推送完成后执行 `git status`，确认没有遗漏文件。
- 本文副本在项目 `docs/更新说明-2026-10-29.md`，会随提交一并上传。

### 遇到冲突或推送被拒绝

- `CONFLICT` 或 `unmerged files`：执行 `git status`，停止继续拉取或推送，将输出交给协作者处理。
- 确认解决完冲突后，才执行 `git add` 标记解决，再根据 `git status` 提示完成当前 rebase 或 merge。
- 仅当没有未解决冲突、工作区干净时，才继续 `git push origin main`。
- 再次出现 `fetch first`：先确认工作区干净，再执行 `git pull --rebase origin main`，成功后重新推送。
- 不使用强制推送覆盖队友提交。
