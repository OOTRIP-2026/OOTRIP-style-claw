# OOTRIP 更新与 GitHub Pages 部署说明（2026-10-28）

## 本次更新

本次更新完善了 AI 穿搭助手的多日穿搭、对话修改和首页同步流程。

本次准备推送的仓库还包含照片／实时试衣、穿搭手账、衣橱详情及静态模块接入更新，完整合并范围见 [本地合并说明](合并说明-2026-10-28.md)。

### 多日穿搭推荐

- 行程超过 4 天时，第 5 天起依次展示新增的三套穿搭。
- 新增穿搭图片已加入源文件和构建输出。
- 进入穿搭助手时先展示常规方案，不再沿用上一次对话的活力配色状态。

### 指定日期修改颜色

- 用户可以输入“第六天颜色更活泼一点”等指令。
- 也可以先提出“希望颜色更活泼”，再补充具体日期。
- 只替换用户指定日期的穿搭，其他日期保持不变。

### 鞋子修改

- 条纹针织衫穿搭默认使用棕色鞋搭配。
- 用户输入“不想穿高跟鞋”后，改为运动鞋版本。
- 修改后的运动鞋卡片会加入最终的首页同步数据。

### 卡片选择与首页同步

- 用户选择修改后的卡片后，小助手提示：

  > 还有想要改的穿搭吗？没有的话我就帮你同步到首页展示啦！

- 用户回复“没有”“不用了”“就这样吧”等结束语时，自动将已确认穿搭同步到首页搭配方案。
- 用户也可以直接点击“结束对话并同步”。
- “不想穿高跟鞋”生成的运动鞋方案可以直接通过结束语或结束按钮同步。

## 推送到 GitHub

仓库地址：<https://github.com/OOTRIP-2026/OOTRIP-style-claw>

在项目根目录执行：

```powershell
npm run build
git status
git add -A
git commit -m "feat: merge fitting, journal, and outfit assistant updates"
git push origin main
```

执行 `git add -A` 前，请先查看 `git status`，确认列出的文件都属于本次需要发布的更新。不要提交 `.env`、密钥、`node_modules` 或个人照片。

## 首次启用 GitHub Pages

本项目已加入 `.github/workflows/deploy-pages.yml`。推送到 `main` 后，GitHub 会自动构建并发布 `dist/`。

1. 打开仓库的 **Settings**。
2. 在左侧选择 **Pages**。
3. 在 **Build and deployment** 中，将 **Source** 设为 **GitHub Actions**。
4. 打开仓库顶部的 **Actions**。
5. 选择 **Deploy OOTRIP to GitHub Pages**，等待工作流显示绿色对勾。
6. 返回 **Settings → Pages**，查看已经生成的公开地址。

预计公开地址：

<https://ootrip-2026.github.io/OOTRIP-style-claw/>

GitHub Pages 地址不包含本地服务使用的 `/app/index.html`。`http://127.0.0.1:3100/app/index.html` 只在你的电脑启动本地服务后可用，不能发给队友远程访问。

## 后续更新部署

以后每次更新时：

1. 在本机执行 `npm run build` 并确认页面效果。
2. 提交并推送到 `main`。
3. 在 GitHub 的 **Actions** 页面等待部署完成。
4. 继续使用同一个 Pages 地址，无需每次生成新链接。

如果推送后页面仍显示旧内容，可以等待 1～3 分钟后强制刷新，或在链接末尾临时加入版本参数：

```text
https://ootrip-2026.github.io/OOTRIP-style-claw/?v=20261028
```

## 部署限制

GitHub Pages 只提供静态页面。穿搭界面、衣橱、本地数据和静态交互可以展示；需要服务端密钥或 Node 后端的实时 AI 试衣、AI 手账等功能，仍需在本机启动完整服务后使用。
